Como o Sistema Funciona

Documentacao completa do Cerebro — o que roda, quando roda, e de onde vem cada informacao.

Visao Geral

O Cerebro e um sistema de gestao pessoal com 3 servicos rodando simultaneamente:

ServicoPortaO que faz
cerebro-bot—Bot Telegram + Scheduler (jobs proativos agendados)
cerebro-web8000Dashboard web (esta interface) + API REST
cerebro-deploy9000Webhook listener para deploy automatico via GitHub

Nginx faz proxy reverso com SSL (HTTPS) + basic auth para todas as rotas exceto webhooks.

Fluxo de uma Mensagem

Quando voce envia uma mensagem no Telegram, o sistema segue este fluxo:

1Telegram Bot recebe a mensagem e verifica autorizacao
2Classificador analisa o texto com regex para detectar intencao (financeiro? tarefa? status?)
3aSe detectou intencao simples → Funcao deterministica responde instantaneamente (sem LLM, custo zero)
3bSe nao detectou → Agente LLM (Claude Sonnet 4) processa com tools e contexto do projeto
4Resposta enviada de volta pelo Telegram

O classificador prioriza respostas deterministicas para economizar tokens. Aproximadamente 60-70% das mensagens sao resolvidas sem LLM.

De Onde Vem as Informacoes

Banco de Dados (SQLite local)

pendencias
Tarefas com projeto, prioridade (P1-P5), prazo, status, responsavel, delegado_para
eventos
Calendario de eventos (sincroniza com Google Calendar)
decisoes
Decisoes registradas por projeto (imutaveis, trilha de auditoria)
fatos_projeto
Conhecimento permanente por projeto (categoria: sobre, meta, restricao, processo, contato)
stakeholders
Pessoas envolvidas em cada projeto + papel e contato
conversas
Historico de mensagens por sessao (multi-turn memory)
lancamentos
Transacoes financeiras (tipo, valor, categoria, projeto, data)
compromissos
Contas a pagar/receber (vencimento, status, parcelas)
jobs
Fila de trabalhos de background (status: pendente → executando → concluido/erro)
metricas
Uso do sistema: tokens consumidos, duracao, taxa de sucesso, erros

Limites: max 50.000 tokens, 30 tool calls, timeout 15 min por job. Modelo: Claude Sonnet 4.

Como o Agente Monta o Contexto

Quando o agente LLM e acionado, o system prompt e montado em camadas:

1Prompt base — Regras gerais, prioridades, tom de voz Hardcoded
2Skill do projeto — Arquivo .md com contexto especifico (pessoas, status, regras) Arquivo
3Pendencias atuais — Tarefas pendentes do projeto Banco
4Decisoes recentes — Ultimas 5 decisoes registradas Banco
5Fatos do projeto — Conhecimento permanente da tabela fatos_projeto Banco
6Historico da conversa — Ultimas mensagens da sessao atual Banco

Total estimado: ~3.000-5.000 tokens de contexto por mensagem, dependendo do projeto.
